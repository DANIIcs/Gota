# Gota — notes for Claude Code

Gota is a native macOS menu-bar app: while dragging files from Finder, holding ⇧ / ⌥ / ⌃ opens a
**Liquid Glass** radial wheel next to the cursor; dropping on a bubble converts or processes the files locally.
The whole point of the project is to look and feel **native to macOS 26+**, so prefer system materials,
SF Symbols, system springs and system frameworks over custom drawing or third-party UI.

## Build & test

The Xcode project is generated by XcodeGen from `project.yml` (the `.xcodeproj` is not committed).

```bash
xcodegen                                                         # after editing project.yml or adding/removing files
xcodebuild -scheme Gota -destination 'platform=macOS' -derivedDataPath build/cli build
xcodebuild -scheme Gota -destination 'platform=macOS' -derivedDataPath build/cli test
```

Use `-derivedDataPath build/cli`: the user usually has Gota running from Xcode (⌘R), and building into Xcode's
DerivedData at the same time breaks code signing ("code object is not signed at all").

Always run `xcodegen` after creating or deleting a `.swift` file, then build. Fix all errors and warnings you introduce.
You cannot see the screen: for anything visual (animations, layout, glass), build, then ask the user to run it (⌘R in
Xcode) and describe what they see.

## Layout

- `Gota/App` — `@main` app (MenuBarExtra + Settings), `AppDelegate` wiring, menu and settings views.
- `Gota/Drag` — `DragMonitor` (global left-mouse-down monitor + 60 Hz polling of `NSPasteboard(name: .drag)` while the
  button is held; no Accessibility permission) and `WheelMode` (modifier key → mode).
- `Gota/Wheel` — `WheelLayout` (pure geometry, unit tested), `WheelModel` (state), `WheelView` (SwiftUI,
  `GlassEffectContainer` + `glassEffect` + `glassEffectID`), `WheelController` + `WheelPanel` (borderless,
  non-activating `NSPanel`).
- `Gota/Conversion` — `Catalog` (which actions per file kind and mode), `WheelAction`, converters
  (`ImageConverter`/ImageIO, `PDFTools`/PDFKit, `MediaConverter`/AVFoundation + afconvert, `FileActions`),
  `DocumentEngines` (Word/PowerPoint via AppleScript, opt-in → LibreOffice headless → Keynote → built-in TextKit
  `DocumentRenderer`; ordered by measured fidelity, see docs/MOTORES.md), `Output`, `Shell`.
- `Gota/Support` — `JobRunner` (runs actions off the main actor, recent results), `Notifier`. Info.plist and
  entitlements here are **generated by XcodeGen**: edit `project.yml`, not those files.
- `Engines/` — bundled third-party pieces: `docxide/` (pinned build of the .docx engine: `build.sh`, `REVISION`,
  `metric-clones.patch`; the binary goes to `build/engines/` and is copied into `Contents/MacOS` by a build phase,
  optional so Gota builds without Rust), `Fonts/` (Carlito, Caladea) and `Licenses/` (shipped in the app).
- `Gota/Resources/AppIcon.icon` — the app icon, an Icon Composer document (layers in `Assets/`, Liquid Glass, all
  system icon styles). Edit it in Icon Composer (Xcode → Open Developer Tool), not by hand.
- `GotaTests` — XCTest unit tests for pure logic.
- `docs/` — Spanish docs: `COMO-FUNCIONA.md` (how engines are picked, run and bundled), `INSTALAR.md` (end users), `GUIA.md` (development + releases), `MOTORES.md` (document
  engines research), `AGREGAR-CONVERSION.md`, `RELEASE-NOTES.md` (body of the next GitHub release).
- `scripts/release.sh` — Release build → `dist/Gota-<version>.zip` + SHA-256; `--publish` tags and uploads it.

## Rules

- Target **macOS 26+**, Swift 5 language mode. UI state classes are `@MainActor`. Callbacks from AppKit that arrive on
  the main thread use `MainActor.assumeIsolated`.
- Conversions must never overwrite: always `Output.file(for:extension:suffix:)`.
- External tools only through `Shell.run(executable, [args])` — never build a shell string, never `sh -c`.
- Prefer built-in frameworks (ImageIO, PDFKit, AVFoundation, Vision, afconvert, textutil). Optional external engines
  (ffmpeg, pandoc, LibreOffice) must be detected, never required.
- Everything runs locally: no network calls, no telemetry. The only exceptions: `UpdateChecker` (on click, or daily if opted
  in) and `GoogleFonts` (downloads an open font a document needs and the Mac lacks; never sends the document; can be
  turned off). Never add other requests, and never send file contents anywhere.
- The wheel panel must stay a drop target over its whole disc (see the 1%-opacity circle in `WheelDropTarget`, which lives in its own panel below the drag image while the visual `WheelView` panel floats above it and ignores the mouse): if it ever lets
  a drop fall through, Finder would move the user's file.
- Untrusted input: files often come from other people. Never let a conversion embed files a document links to
  (`DocumentRenderer.keepingOnlyImages`, LibreOffice's `BlockUntrustedRefererLinks` profile), cap sizes taken from
  the file (`PDFTools.maxPagePixels`), and add a `SecurityTests` case for each new parser or engine.
- Never commit secrets, `Config/Local.xcconfig` or anything personal; releases go through `scripts/release.sh`.
- Max 8 bubbles per mode. UI text is Spanish for now; keep strings short.
- Add unit tests for logic changes (catalog, geometry, naming). Keep functions small and comment the *why*.
